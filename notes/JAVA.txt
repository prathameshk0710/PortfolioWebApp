What Is the difference between Object and Object Reference?

- Object and object reference are not same
- Object is the real data stored in heap and created using ‘new’ keyword
- Object reference is an address of the object where the object is stored in stack memory.



Does assigning null to a reference deletes the object?

No assigning null does not delete the object its just removes the reference but the object still remains in memory but it is unreachable now. Garbage collector will remove it later.

Why does Java support multiple inheritance using interfaces but not classes?

Java does not allow multiple inheritance with classes because it can create confusion and errors. If two parent classes have the same method or variable name, the child class will not know which one to use. This is called the "diamond problem."
But Java allows multiple inheritance with interfaces because interfaces mainly define method names, not full method code. So there is less confusion. Even when two interfaces have the same method, the child class must write its own implementation, so
Java clearly knows which code to use.

Collections

Its is a framework in java which enables us to maintain and implement data structures.

ArrayList: 
- Dynamic implementation of array
- It is the extension of AbstractList. And implements List interface.
- They are maintained in insertion order
- This will always store Object data types, it wont work on primitive data types
- It is not thread safe.
- Random access with O(1)
- Insertion and deletion in array list and ends is O(1)
- Search in array list is O(n)

Internal working array list
- baseline of array list works on array.
- It creates the space of 10 only when an element is added.
- When arralylist of size 10 is full then arraylist copies the existing array and creates new arraylist with increased with 50% capacity.
- ArrayList is not thread safe. concurrent modification exception may occur.
- we can avoid this by using vector -> slow, locks the entire list for each operation.
- Collection.synchronizedList(), 
- copyOnwirteArrayList.


CopyOnWriteArrayList:
- This is used to avoid the concurrent modification in an arrayList.
- options like Vector and Collection.SynchronizedList() can also be used for  concurrent modification but are slow.
- thats where CoppyOnWriteArraylist comes in picture.
- In this your read operations are always done on snapshot of original array, so that multiple threads with read operation can perform there task.
- Whereas in case of write operation it writes on original array where a single thread is locked while performing write operation, and then later copy it to snapshot array.
- this will get high performance and concurrency


Hash Map:
- It stores the data in the form of key value based pair.
- We use array and LinkedList to create hashMap
- Its key is converted into a hash using a hashing algorithm
- if two objects are equale than hash will be equal, if two hash codes are equal than objects may or may not be equal.
- we need hash code to calculate bucket to know which bucket to store data in.
- default 16 bucket, and load factor is 75%. if 75% of bucket is filled then bucket size is increased.
- Collision: 
    - It is the concept when an algorithm generates same hashCode for two different object.
    - .put()
        - If object is also same then hashmap replace the old value with new value.
        - if object is not same then the old node(old object) will point to new node, like a linkedList.
        - in Node of a hashMap we store, hash code, key, value, next Pointer.
    - .get()
        - it calculates the hashCOde of a key to be find, then go on that location and iterate the linkedList at that address.
- After java 8 when bucket in hashmap has more than a certain number of elements, it switches from using linked list to a balanced tree to stroe the key value pair, so the time complexcity decreased to log(n).
- It is not thread safe.

Concurrent hashMap:
- It is to be used when there is concurrent modification in hashmap
- It is a bucket level locking, means complete hashmap isnt loccked it only locks the bucket wehre the new element is to be added.
- read operations are happening concurrently, as write operations are happening on bucket level the individual bucket can be locked while writing.
- better performance, thread safety achived.
- Collection.synchronizedmap() can we added to hashmap but that will lock the complete map so thats why the concurrent map can be used.


Hash Set:
- stores unique values
- backed by hashmap, which garante uniqueness.
- doesnt maintain insertion order.
- it is not thread safe.
